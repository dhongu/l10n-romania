Overview

A register of the e-Factura (SPV) messages for Odoo Online too: the module has no Python code and is imported as a zip (Apps > Import Module). It works on top of the standard Romanian e-Factura module (l10n_ro_edi), which sends the invoices and downloads the vendor bills; this module only shows what the standard module already keeps, in one place.

  • SPV Messages menu
    in Accounting (Invoicing): the last SPV message of each invoice sent and each bill received, grouped by status (Sent, Validated, Error).
  • Filters
    sent / received, waiting for ANAF, validated, refused, with an error message, by date; group by status, direction, partner or month.
  • Message form
    the invoice, the partner, the total, the message of ANAF, the download key, the XML of the message (the invoice sent, or the signature of ANAF) and the files of the invoice (the XML and the PDF of a received bill), all downloadable. The list shows the partner and the date of the invoice; the total is on the form.
  • Synchronize now
    runs the standard synchronization with the SPV (status of the invoices sent, new vendor bills) without waiting for the scheduled action; on a company without a Tax ID or without an SPV token, it says what to set first.

What it does not do: it does not match the products by the vendor code or create the partners from the CUI; on a server with Python, the OCA module l10n_ro_message_spv does that. The ANAF token stays in your database; apart from the standard synchronization with the SPV of ANAF, the module sends no data anywhere.

Usage

Before: the company has a Tax ID and is connected to the SPV in Invoicing (Accounting) > Configuration > Settings, block Romanian E-Factura (Client ID, Client Secret, Generate Token), as for the standard module.

  1. Go to Invoicing > SPV Messages (Accounting > SPV Messages). The messages are grouped by status: Error, Sent (waiting for ANAF), Validated. Received is ticked on the vendor bills downloaded from the SPV.
1 The SPV Messages register grouped by status: one invoice in Error with the BR-RO-110 message, one Sent and four Validated, two of them vendor bills ticked in the Received column; the Synchronize now button and the SPV Messages menu are highlighted
  1. Open the filters: Sent / Received show only the invoices sent or only the bills received, Refused the invoices refused by ANAF and Errors the messages with an error text. Group by Status, Direction, Partner or Date.
2 The filter menu open over the register: Sent, Received, Refused and Errors highlighted; on the right, Group By Status (ticked), Direction, Partner and Date
  1. Open a received bill: the invoice is linked at the top; XML of the message downloads the signature of ANAF and Invoice files holds the XML and the PDF of the vendor bill.
3 The SPV message of the vendor bill BILL/2026/11/0002 from Gama Logistic SRL, validated: Received ticked, the download key 5012345674 and, under Files, the signature XML plus the PDF and the XML of the bill, highlighted
  1. Open a refused invoice: Message gives the reason of ANAF. Correct the invoice and send it again from the invoice, as in the standard module. On an invoice still waiting for ANAF, Fetch status asks ANAF for that invoice only.
4 The SPV message of the invoice INV/2026/00012 in Error: the Message block, highlighted, with E: BR-RO-110 and the reason given by ANAF
  1. Click Synchronize now to fetch the latest messages from ANAF: the status of the invoices sent and the new vendor bills, created as drafts. On a company without a Tax ID or not connected to the SPV, the button says what to set first. The button is for the users with invoicing rights.
5 The Invalid Operation window after Synchronize now on a company not connected: The company RO Company is not connected to the SPV yet, with the path Invoicing (Accounting) > Configuration > Settings, Romanian E-Factura, Generate Token
