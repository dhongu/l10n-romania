Overview

Modulul adaugă controale suplimentare peste evaluarea stocului din localizarea românească (l10n_ro_stock_account), ca valorile ajunse în contabilitate să nu fie zero sau fără sursă.

Funcții principale

  • Preț de cost nenul pe mișcările de stoc
    calculul prețului unitar al unor mișcări reale de stoc (stock.move._get_price_unit) se oprește cu o eroare când iese zero — de exemplu, la validarea livrării unei mărfi fără cost cu modulul de marjă sale_stock_margin instalat, la închiderea sesiunii de punct de vânzare sau în raportul comenzii de producție. Fără sale_stock_margin, livrarea se validează. Prețul folosit la costul vânzării (COGS) de pe factură nu este verificat.
  • Facturi cu produse stocabile doar din comenzi
    la validarea unei facturi de vânzare sau de achiziție (inclusiv storno), fiecare linie cu produs stocabil trebuie să provină dintr-o linie de comandă de vânzare (SO), respectiv de achiziție (PO). Liniile cu servicii nu sunt verificate.
  • Restricția se activează din setări
    Setări → România → Contabilitate, opțiunea Verifică sursa liniei de produs stocabilă (implicit dezactivată).

Parametri de sistem

  • l10n_ro_stock_account.check_storable_line_source — parametrul din spatele opțiunii din setări (True / False).
  • l10n_ro_stock_account.skip_price_unit_check — pus pe True, dezactivează verificarea prețului de cost nenul (implicit verificarea este activă).

Usage

The module adds two controls that protect the stock accounting entries.

1. Storable product lines must come from an order (optional)

Go to Invoicing → Configuration → Settings, open România in the left panel and tick Check storable product line source, then Save. The option applies to the whole database.

With the option on, a customer invoice or credit note with a storable product that does not come from a sales order cannot be confirmed: Confirm shows "Invoice line with storable product '...' must have a reference to a sales order line." Invoice from the sales order instead.

Vendor bills and refunds work the same way: a storable product line must come from a purchase order (fill the bill from the purchase order with Auto-Complete).

Lines with services or consumables are not checked.

2. Stock moves must have a unit price (always on)

When Odoo computes the unit price of real stock moves and gets 0, the operation stops with "Price unit is not set for product ...". For example, validating the delivery of a FIFO product without cost from a sales order (with the sales margin module installed) is blocked, and the delivery stays Ready. Set the product cost, or receive the goods with a price, then validate again.

Computations on an empty set of moves (for example, the returns of a delivery that has none) are not checked.

System parameters

In developer mode, Settings → Technical → Parameters → System Parameters shows l10n_ro_stock_account.check_storable_line_source (written by the setting above) and, if created, l10n_ro_stock_account.skip_price_unit_check. Set the latter to True only to allow moves without cost temporarily (for example, an opening stock at zero cost), then back to False.
